  How It Works (Complete Flow)                                                  
                                                                                
  1. User logs in → Backend sets csrf_token cookie (httpOnly=false)             
  2. Frontend makes POST/PUT/DELETE/PATCH request                               
     → Request interceptor reads csrf_token from cookie                         
     → Adds X-CSRF-Token header to request                                      
  3. Backend validates: cookie value === header value                           
     → If match: request proceeds                                               
     → If mismatch: returns 403 with CSRF error code                            
  4. If CSRF error → Response interceptor redirects to login

  So Sánh: Explicit vs Event-Driven                                             
  ┌──────────────────┬─────────────────────────────┬───────────────────────────┐
  │     Tiêu chí     │     Explicit (Hiện tại)     │       Event-Driven        │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Complexity       │ ✅ Simple, dễ hiểu          │ ⚠️ Phức tạp hơn           │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Transaction      │ ✅ Cùng transaction, đảm    │ ⚠️ Cần quản lý            │
  │ Safety           │ bảo atomicity               │ transaction boundary      │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Debugging        │ ✅ Stack trace rõ ràng      │ ⚠️ Event chain khó trace  │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Coupling         │ ⚠️ Tightly coupled          │ ✅ Loosely coupled        │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Extensibility    │ ⚠️ Thêm handler = thêm call │ ✅ Chỉ register thêm      │
  │                  │  site                       │ handler                   │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Maintainability  │ ⚠️ Có thể quên gọi sync     │ ✅ Tự động trigger        │
  ├──────────────────┼─────────────────────────────┼───────────────────────────┤
  │ Performance      │ ✅ Không overhead           │ ⚠️ Dispatch overhead nhỏ  │
  └──────────────────┴─────────────────────────────┴───────────────────────────┘

  Đánh Giá Rủi Ro                                                               
                                                                                
  Rủi ro của Explicit Approach                                                  
  Rủi ro: Quên gọi sync khi thêm status transition mới                          
  Xác suất: LOW                                                                 
  Tác động: HIGH                                                                
  Mitigation hiện có: Code review, tests                                        
  ────────────────────────────────────────                                      
  Rủi ro: Inconsistent nếu sync fail                                            
  Xác suất: LOW                                                                 
  Tác động: MEDIUM                                                              
  Mitigation hiện có: ✅ Cùng transaction, rollback tự động                     
  ────────────────────────────────────────                                      
  Rủi ro: Khó extend cho feature mới                                            
  Xác suất: MEDIUM                                                              
  Tác động: LOW                                                                 
  Mitigation hiện có: Chấp nhận được với scope hiện tại

  user_id):

  on_admission_status_changed)

  await dispatcher.dispatch(                                                    
      TransportEvents.ADMISSION_STATUS_CHANGED,                                 
      db=db,                                                                    
      profile_id=profile.id,

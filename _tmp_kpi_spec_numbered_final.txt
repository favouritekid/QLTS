   1: # KPI Planning Engine — Reverse-Funnel Spec
   2: 
   3: > **Trạng thái**: Đã chốt — sẵn sàng implement
   4: > **Input**: 1 con số (annual enrollment target) → Output: 8 KPI × 12 tháng
   5: > **Revision**: v3 — chuẩn hóa kiểu dữ liệu (NUMERIC), canonical KPI codes, historical target resolution
   6: 
   7: ---
   8: 
   9: ## 1. Tổng quan mô hình
  10: 
  11: ```
  12: Admin nhập: enrollments_annual = 300
  13:                     ↓
  14:          Seasonal Weights (12 tháng)
  15:                     ↓
  16:          M_t = enrollments_monthly per tháng
  17:                     ↓
  18:     ┌───────────────┼───────────────┐
  19:     ↓               ↓               ↓
  20:  DERIVED         DERIVED        GUARDRAIL
  21:  (từ M_t +       (từ M_t +      (policy,
  22:   historical)     forecast)      không đổi
  23:                                  theo volume)
  24: ```
  25: 
  26: ### 3 lớp KPI
  27: 
  28: | Lớp | KPI codes | Logic |
  29: |-----|-----------|-------|
  30: | **Anchor** | `enrollments_annual`, `enrollments_monthly` | Input + phân bổ seasonal |
  31: | **Derived** | `consultations_daily`, `conversion_rate`, `win_rate`, `consultation_effectiveness` | Tính ngược từ M_t + k_t/L_t/C_t |
  32: | **Guardrail** | `sla_compliance_rate`, `response_time_hours` | Chính sách, admin set trực tiếp |
  33: 
  34: ### Định nghĩa biến
  35: 
  36: | Biến | Ý nghĩa |
  37: |------|---------|
  38: | `M_t` | Chỉ tiêu nhập học tháng t |
  39: | `k_t` | Hệ số tư vấn — số lượt tư vấn cần thiết để có 1 nhập học |
  40: | `WD_t` | Số ngày làm việc (T2-T7, trừ lễ) trong tháng t |
  41: | `L_t` | Dự báo số leads mới trong tháng t |
  42: | `C_t` | Dự báo số leads đóng (won + lost) trong tháng t |
  43: | `consulted_closed_t` | Số leads đã tư vấn ít nhất 1 lần VÀ đã đóng (won hoặc lost) trong tháng t. Dùng để đo hiệu quả tư vấn: bao nhiêu % leads được tư vấn cuối cùng chuyển đổi thành nhập học |
  44: 
  45: ### Công thức quy đổi 8 KPI cho tháng t
  46: 
  47: ```
  48: enrollments_annual      = 300                           (input)
  49: enrollments_monthly_t   = round(300 × weight_t)         (seasonal, có reconciliation)
  50: consultations_daily_t   = ceil(M_t × k_t / WD_t)        (reverse-funnel, WD_t=0 → NULL)
  51: conversion_rate_t       = (M_t / L_t) × 100             (reverse-funnel, guard: L_t > 0)
  52: win_rate_t              = (M_t / C_t) × 100              (reverse-funnel, guard: C_t > 0)
  53: consultation_effectiveness_t = max(floor, M_t / consulted_closed_t × 100)  (guard: consulted_closed_t > 0)
  54: sla_compliance_rate_t   = guardrail (e.g. 85%)           (policy)
  55: response_time_hours_t   = guardrail (e.g. 2h)            (policy)
  56: ```
  57: 
  58: ### Reconciliation — đảm bảo sum(M_t) == annual_target (Largest Remainder Method)
  59: 
  60: ```python
  61: # Bước 1: Tính M_t thô (giữ phần thập phân)
  62: exact = [annual_target * w for w in weights]
  63: floored = [math.floor(x) for x in exact]
  64: 
  65: # Bước 2: Tính diff cần phân bổ (có thể dương HOẶC âm)
  66: diff = annual_target - sum(floored)
  67: 
  68: # Bước 3: Sắp xếp tháng theo phần lẻ (remainder) giảm dần
  69: remainders = [(i, exact[i] - floored[i]) for i in range(12)]
  70: remainders.sort(key=lambda x: x[1], reverse=True)
  71: 
  72: if diff > 0:
  73:     # Bước 4a: Thiếu → cộng 1 cho diff tháng có remainder lớn nhất
  74:     for i in range(diff):
  75:         floored[remainders[i][0]] += 1
  76: elif diff < 0:
  77:     # Bước 4b: Thừa (tổng weights > 1.0) → trừ 1 cho |diff| tháng có remainder nhỏ nhất
  78:     for i in range(abs(diff)):
  79:         floored[remainders[-(i+1)][0]] -= 1
  80: 
  81: # Kết quả: sum(floored) == annual_target, cả khi tổng weights > 1 hoặc < 1
  82: # Ví dụ 1: annual=300, weights sum=0.998 → floor sum=293, diff=+7 → cộng 1 cho 7 tháng top remainder
  83: # Ví dụ 2: annual=300, weights sum=1.002, diff=-1 → trừ 1 cho tháng bottom remainder
  84: ```
  85: 
  86: ### Division-by-zero & NULL semantics (2 lớp)
  87: 
  88: **Lớp 1: Planning internal (`kpi_plan_month`)** — nullable, ghi nhận "không tính được"
  89: 
  90: ```python
  91: # Rule duy nhất: WD_t cho phép = 0 (tháng nghỉ toàn bộ)
  92: # Khi WD_t = 0:
  93: consultations_daily_t = NULL     # Không tính được
  94: conversion_rate_t = NULL
  95: win_rate_t = NULL
  96: consultation_effectiveness_t = NULL
  97: 
  98: # Khi L_t = 0 hoặc C_t = 0:
  99: conversion_rate_t = NULL
 100: win_rate_t = NULL
 101: 
 102: # Khi consulted_closed_t = 0:
 103: consultation_effectiveness_t = floor  # Fallback về floor (50%)
 104: 
 105: # Khi M_t = 0 (weight rất nhỏ + annual_target nhỏ):
 106: consultations_daily = 0          # Hợp lệ: 0 tư vấn cần thiết
 107: conversion_rate = NULL
 108: win_rate = NULL
 109: consultation_effectiveness = floor
 110: ```
 111: 
 112: **Lớp 2: Dashboard contract (`KPIStats`, `KpiConfig`)** — non-null, luôn trả số
 113: 
 114: ```python
 115: # Dashboard schemas hiện tại dùng non-null float (KPIStats.win_rate: float = 0.0)
 116: # KHÔNG đổi contract này. Giữ backward compatible.
 117: 
 118: # Sync job xử lý NULL → non-null:
 119: # Khi kpi_plan_month field = NULL:
 120: #   → Sync job KHÔNG upsert KpiConfig cho kpi_code đó
 121: #   → get_kpi_target() fallback về DEFAULT_KPIS (luôn trả số)
 122: #   → Dashboard hiện DEFAULT value — chấp nhận cho edge case hiếm (WD_t=0)
 123: 
 124: # Admin Planning UI (GET /plans/{id}) — dùng schema riêng:
 125: #   → Response trả Optional[float] cho derived fields
 126: #   → Admin UI hiện "N/A" khi NULL
 127: #   → Không ảnh hưởng officer dashboard schema
 128: ```
 129: 
 130: > **Tóm tắt**: NULL chỉ tồn tại trong `kpi_plan_month` table và Admin Planning API.
 131: > Officer dashboard contract (`KPIStats`, `get_kpi_target()`) **không thay đổi** — luôn non-null.
 132: > Edge case WD_t=0 cực hiếm (tháng toàn nghỉ lễ = gần như không xảy ra thực tế).

 136: ## 2. Quyết định đã chốt
 137: 
 138: ### 2.1 Scope & Inheritance
 139: 
 140: ```
 141: Officer KpiPlanMonth  →  Unit KpiPlanMonth  →  Global KpiConfig  →  DEFAULT_KPIS
 142:    (nếu có)                (mặc định)           (fallback)          (hardcode)
 143: ```
 144: 
 145: - **Unit plan** = mặc định. Manager tạo plan cho unit, áp dụng tất cả officers.
 146: - **Officer override** = tùy chọn per tháng. Khi officer cần target cá nhân hóa.
 147: - **Officer plan** khi có: override **toàn bộ 8 KPI** cho tháng đó (không partial merge với unit plan). Lý do: tránh logic kế thừa phức tạp, admin set rõ ràng.
 148: - Sync job: lấy effective target theo inheritance chain trên.
 149: 
 150: #### Bảng precedence cho 1 KPI field cụ thể (VD: `consultations_daily` tháng T3)
 151: 
 152: | # | Source | Điều kiện | Ví dụ |
 153: |---|--------|-----------|-------|
 154: | 1 | **Officer plan month field override** | Officer plan tồn tại + field nằm trong `overridden_fields` | Admin override Officer A T3: `consultations_daily = 20` |
 155: | 2 | **Officer plan month derived** | Officer plan tồn tại + field KHÔNG trong `overridden_fields` | Officer A plan tính ra `consultations_daily = 13` |
 156: | 3 | **Unit plan month field override** | Không có officer plan + field nằm trong `overridden_fields` | Manager override unit T3: `consultations_daily = 15` |
 157: | 4 | **Unit plan month derived** | Không có officer plan + field KHÔNG trong `overridden_fields` | Unit plan tính ra `consultations_daily = 12` |
 158: | 5 | **Global KpiConfig** | Không có plan nào (hoặc plan inactive) | Admin set global `consultations_daily = 10` |
 159: | 6 | **DEFAULT_KPIS (hardcode)** | Không có KpiConfig record | `DEFAULT_KPIS["consultations_daily"] = 10` |
 160: 
 161: > **Quy tắc**: Đi từ trên xuống, dừng ở level đầu tiên tìm thấy giá trị.
 162: > Officer plan khi có sẽ bỏ qua toàn bộ unit plan (không partial merge).
 163: > `overridden_fields` chỉ ảnh hưởng bên trong cùng 1 plan (sync job skip recalculate field đó).
 164: 
 165: ### 2.2 Mặc định năm đầu (chưa có data lịch sử)
 166: 
 167: | Biến | Default | Ý nghĩa |
 168: |------|---------|---------|
 169: | `k_t` | 7 | 7 tư vấn để có 1 nhập học |
 170: | `L_t` | `6 × M_t` | Conversion target mặc định ~16.7% |
 171: | `C_t` | `3 × M_t` | Win rate target mặc định ~33.3% |
 172: | `consultation_effectiveness` floor | 50% | Khi chưa đủ data |
 173: 
 174: > **Cần thêm** `win_rate` vào `DEFAULT_KPIS` trong `kpi_service.py` (hiện chỉ có 7 codes, thiếu `win_rate`):
 175: > ```python
 176: > DEFAULT_KPIS["win_rate"] = 33  # 33% — consistent với C_t = 3 × M_t
 177: > ```
 178: 
 179: ### 2.3 Auto-calibration (từ tháng thứ 4+)
 180: 
 181: - **Nguồn**: Rolling 3 tháng gần nhất (EMA — Exponential Moving Average)
 182: - **Damping**: Giới hạn thay đổi ±15%/tháng so với tháng trước
 183: - **Lần đầu từ default**: Cho phép ±30% (vì default có thể xa thực tế)
 184: - **Không áp dụng cho**: Ô đã override thủ công (field nằm trong `overridden_fields`)
 185: 
 186: ```python
 187: # EMA calculation
 188: k_new = 0.5 * k_actual_this_month + 0.3 * k_prev + 0.2 * k_prev_prev
 189: 
 190: # Damping
 191: if is_first_calibration:  # Lần đầu chuyển từ default sang actual
 192:     k_clamped = clamp(k_new, k_current * 0.70, k_current * 1.30)
 193: else:
 194:     k_clamped = clamp(k_new, k_current * 0.85, k_current * 1.15)
 195: ```
 196: 
 197: #### Fallback khi < 3 tháng data
 198: 
 199: ```python
 200: if months_with_data == 0:
 201:     return default_value  # k=7, L=6×M, C=3×M
 202: 
 203: if months_with_data == 1:
 204:     k_new = k_actual_month_1  # Dùng trực tiếp, không EMA
 205: 
 206: if months_with_data == 2:
 207:     k_new = 0.6 * k_actual_month_2 + 0.4 * k_actual_month_1
 208: 
 209: if months_with_data >= 3:
 210:     k_new = 0.5 * k_month_3 + 0.3 * k_month_2 + 0.2 * k_month_1  # Full EMA
 211: ```
 212: 
 213: ### 2.4 Working days
 214: 
 215: - **Tự động**: Thứ 2-7 (T2-T7), loại trừ ngày lễ VN từ bảng `holiday_calendar`
 216: - **Admin override**: Có thể sửa WD_t per tháng (bù ngày làm đặc biệt)
 217: - **Audit**: Lưu `overridden_by`, `overridden_at` khi sửa
 218: - **Cho phép WD_t = 0**: Tháng toàn nghỉ lễ → derived KPIs = NULL, sync skip (xem section 1 "Division-by-zero & NULL semantics")
 219: 
 220: ### 2.5 Override KPI derived — Per-field granularity
 221: 
 222: - **Cho phép**: Admin/Manager override bất kỳ KPI derived nào per tháng
 223: - **Granularity**: Override theo **từng field**, không phải cả row
 224: - **Bắt buộc**: `override_reason`, `overridden_by`, `overridden_at`, `overridden_fields` (JSONB)
 225: - **Sync protection**: Job monthly KHÔNG ghi đè field nằm trong `overridden_fields`
 226: - **Reset**: Admin có thể "reset về auto" → xóa field khỏi `overridden_fields`, job tính lại field đó
 227: - **IDOR**: Xem section 2.6 bên dưới

 229: ### 2.6 Security: IDOR Dependencies (MANDATORY)
 230: 
 231: > **Tuân thủ**: `Backend_FastAPI/AUTHORIZATION_GUIDELINES.md` — KHÔNG dùng `if` trong
 232: > Router/Service để check quyền. LUÔN trả 404, KHÔNG BAO GIỜ trả 403.
 233: 
 234: ```python
 235: # app/core/deps.py — Dependency mới cho KPI Planning
 236: 
 237: async def get_kpi_plan_for_user(
 238:     plan_id: int,
 239:     db: AsyncSession = Depends(get_db),
 240:     current_user: User = Depends(get_current_active_user),
 241: ) -> KpiPlan:
 242:     """
 243:     IDOR-safe: Admin thấy tất cả, Manager chỉ thấy plan thuộc unit mình.
 244:     Trả 404 nếu không tìm thấy HOẶC không có quyền (chống inference).
 245:     """
 246:     plan = await kpi_planning_repo.get_by_id(db, plan_id)
 247:     if not plan or not plan.is_active:
 248:         raise ResourceNotFoundError("KpiPlan", plan_id)  # 404
 249:     if current_user.role == "admin":
 250:         return plan
 251:     if current_user.role == "manager" and plan.unit_id == current_user.unit_id:
 252:         return plan
 253:     raise ResourceNotFoundError("KpiPlan", plan_id)  # 404, KHÔNG 403
 254: 
 255: 
 256: async def get_kpi_plan_month_for_user(
 257:     month_id: int,
 258:     db: AsyncSession = Depends(get_db),
 259:     current_user: User = Depends(get_current_active_user),
 260: ) -> KpiPlanMonth:
 261:     """
 262:     IDOR-safe cho plan month. Join plan → check unit scope.
 263:     """
 264:     month = await kpi_planning_repo.get_month_with_plan(db, month_id)
 265:     if not month or not month.plan.is_active:
 266:         raise ResourceNotFoundError("KpiPlanMonth", month_id)
 267:     if current_user.role == "admin":
 268:         return month
 269:     if current_user.role == "manager" and month.plan.unit_id == current_user.unit_id:
 270:         return month
 271:     raise ResourceNotFoundError("KpiPlanMonth", month_id)
 272: ```
 273: 
 274: ```python
 275: # Router sử dụng — KHÔNG có logic check quyền trong router body
 276: @router.put("/months/{month_id}/override")
 277: async def override_month(
 278:     overrides: OverrideRequest,
 279:     month: KpiPlanMonth = Depends(get_kpi_plan_month_for_user),  # IDOR ở đây
 280:     db: AsyncSession = Depends(get_db),
 281: ):
 282:     result, callback = await kpi_planning_service.override_month_kpi(...)
 283:     await db.commit()
 284:     if callback: await callback()
 285:     return result
 286: ```

 302: ### 3.1 Prerequisite migration: `KpiConfig.target_value` Integer → NUMERIC
 303: 
 304: ```sql
 305: -- KpiConfig hiện tại lưu target_value dạng INTEGER.
 306: -- Các KPI như conversion_rate (16.7%), win_rate (33.3%) cần thập phân.
 307: -- Migration cần chạy TRƯỚC khi planning sync bắt đầu ghi dữ liệu.
 308: 
 309: -- CHỈ KpiConfig.target_value cần NUMERIC (vì chứa cả rates lẫn counts)
 310: ALTER TABLE kpi_config
 311:     ALTER COLUMN target_value TYPE NUMERIC(12,2) USING target_value::NUMERIC(12,2);
 312: 
 313: -- KpiTarget: GIỮ INTEGER — chỉ đếm enrollment (không có tỷ lệ)
 314: -- annual_target = 300 (hồ sơ), achieved_ytd = 67 (hồ sơ) → luôn nguyên
 315: -- Nếu sau này thêm kpi_code khác cần decimal, tạo bảng mới thay vì sửa
 316: 
 317: -- KpiMonthlySnapshot: GIỮ INTEGER — cùng semantics với KpiTarget

 321: > **Backward compatible**: Existing integer values trong KpiConfig (e.g. 10, 85) tự cast sang
 322: > NUMERIC (10.00, 85.00). Code hiện tại so sánh `>`, `<` vẫn hoạt động.
 323: 
 324: ```python
 325: # Schema/API changes CHỈ cho KpiConfig:
 326: #   KpiConfigCreate.target_value: int → float (Pydantic)
 327: #   KpiConfigResponse.target_value: int → float
 328: #   get_kpi_target() return type: int → float
 329: #   get_all_kpi_targets() return type: Dict[str, int] → Dict[str, float]

 331: # KpiTarget/KpiMonthlySnapshot schemas: KHÔNG ĐỔI (giữ int)

 334: ### 3.2 Bảng mới: `kpi_plan`
 335: 
 336: ```sql
 337: CREATE TABLE kpi_plan (
 338:     id              INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 339:     unit_id         INTEGER NOT NULL REFERENCES organization_unit(id) ON DELETE CASCADE,  -- bắt buộc, không có global plan
 340:     officer_id      INTEGER REFERENCES "user"(id) ON DELETE CASCADE,  -- NULL = unit plan
 341:     fiscal_year     INTEGER NOT NULL,
 342: 
 343:     -- Anchor input
 344:     annual_enrollment_target  INTEGER NOT NULL,  -- 300
 345: 
 346:     -- Guardrails
 347:     sla_target              NUMERIC(5,2) NOT NULL DEFAULT 85.00,   -- %
 348:     response_time_target    NUMERIC(5,2) NOT NULL DEFAULT 2.00,    -- hours
 349: 
 350:     -- Seasonal weights (JSON array of 12 floats, sum ≈ 1.0)
 351:     -- NULL = dùng DEFAULT_ENROLLMENT_WEIGHTS
 352:     seasonal_weights        JSONB,
 353: 
 354:     -- Meta
 355:     is_active       BOOLEAN NOT NULL DEFAULT TRUE,
 356:     created_by      INTEGER REFERENCES "user"(id),
 357:     created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
 358:     updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
 359: );
 360: 
 361: -- ⚠️ PostgreSQL: NULL != NULL trong unique index.
 362: -- Nếu officer_id IS NULL (unit plan), 1 index gộp sẽ cho phép duplicate.
 363: -- Giải pháp: 2 partial indexes tách biệt.
 364: 
 365: -- Unit plan: 1 plan active per unit per year
 366: CREATE UNIQUE INDEX uix_kpi_plan_active_unit
 367: ON kpi_plan (unit_id, fiscal_year)
 368: WHERE is_active = TRUE AND officer_id IS NULL;
 369: 
 370: -- Officer plan: 1 plan active per officer per unit per year
 371: CREATE UNIQUE INDEX uix_kpi_plan_active_officer
 372: ON kpi_plan (unit_id, officer_id, fiscal_year)
 373: WHERE is_active = TRUE AND officer_id IS NOT NULL;
 374: 
 375: COMMENT ON TABLE kpi_plan IS 'KPI planning — reverse-funnel từ annual target ra 8 KPI × 12 tháng';
 376: ```
 377: 
 378: ### 3.3 Bảng mới: `kpi_plan_month`
 379: 
 380: ```sql
 381: CREATE TABLE kpi_plan_month (
 382:     id              INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 383:     plan_id         INTEGER NOT NULL REFERENCES kpi_plan(id) ON DELETE CASCADE,
 384:     month           INTEGER NOT NULL CHECK (month BETWEEN 1 AND 12),
 385: 
 386:     -- Distributable inputs
 387:     enrollment_target       INTEGER NOT NULL,            -- M_t: 46
 388:     working_days            INTEGER NOT NULL DEFAULT 0,  -- WD_t: 26 (0 = tháng nghỉ toàn bộ)
 389:     weight                  NUMERIC(6,4) NOT NULL,       -- 0.1530
 390: 
 391:     -- Historical factors (computed or manual)
 392:     k_factor                NUMERIC(6,2) NOT NULL DEFAULT 7.00,  -- k_t
 393:     lead_forecast           INTEGER,                     -- L_t (NULL = 6×M_t)
 394:     close_forecast          INTEGER,                     -- C_t (NULL = 3×M_t)
 395: 
 396:     -- Derived KPI targets (auto-calculated, overridable per-field)
 397:     -- NULL = không tính được (WD_t=0, M_t=0, etc.) → UI hiển thị "N/A"
 398:     consultations_daily     INTEGER,                     -- NULL khi WD_t=0
 399:     conversion_rate         NUMERIC(6,2),                -- % (NULL khi L_t=0)
 400:     win_rate                NUMERIC(6,2),                -- % (NULL khi C_t=0)
 401:     consultation_effectiveness NUMERIC(6,2),             -- %
 402: 
 403:     -- Per-field override tracking
 404:     -- Ví dụ: {"consultations_daily": true, "win_rate": true}
 405:     -- Sync job chỉ skip field nằm trong JSONB này, các field khác vẫn recalculate
 406:     overridden_fields       JSONB NOT NULL DEFAULT '{}',
 407:     override_reason         TEXT,           -- DB nullable, nhưng API enforce NOT NULL khi overridden_fields != '{}'
 408:     overridden_by           INTEGER REFERENCES "user"(id),  -- idem

 522:       1. M_t = round(annual × weight_t) + Largest Remainder reconciliation
 523:       2. WD_t = count_working_days(year, month) — từ holiday_calendar
 524:       3. k_t = get_k_factor(officer_id, month) hoặc default 7
 525:       4. L_t = lead_forecast hoặc 6 × M_t
 526:       5. C_t = close_forecast hoặc 3 × M_t

 528:     Skip field nằm trong overridden_fields (per-field, không skip cả row).
 529:     """

 531: async def preview_plan(db, unit_id, fiscal_year, annual_target,
 532:                        guardrails, seasonal_weights=None):
 533:     """
 534:     Dry-run: tính 12 bộ KPI KHÔNG persist.
 535:     Trả về cấu trúc giống GET /plans/{id} nhưng không tạo record.
 536:     Frontend gọi endpoint này (debounced) khi admin kéo thanh weights.
 537:     ⚠️ KHÔNG có db.flush() — pure computation, read-only.
 538:     """
 539: 
 540: async def recalibrate_factors(db, plan_id, up_to_month):
 541:     """
 542:     Auto-calibration: dùng actual data 3 tháng gần nhất → update k_t, L_t, C_t.
 543:     Damping: ±15% max change (±30% cho lần đầu từ default).
 544:     Fallback: < 3 tháng data → simple average thay vì EMA.
 545:     Chỉ update tháng future, không sửa tháng đã qua.
 546: 
 547:     Phát hiện is_first_calibration:
 548:       Truy vấn: có tồn tại kpi_plan_month nào thuộc plan scope (cùng unit/officer)
 549:       có actual_enrollments IS NOT NULL không?
 550:       - Nếu KHÔNG → is_first_calibration = True → damping ±30%
 551:       - Nếu CÓ → is_first_calibration = False → damping ±15%
 552:     """
 553: 
 554: async def update_plan(db, plan_id, annual_target=None, weights=None,
 555:                       guardrails=None, user_id=None):
 556:     """
 557:     Sửa plan metadata.
 558:     Nếu sửa annual_target giữa năm:
 559:       - Redistribute cho tháng current + future (giữ nguyên actual tháng đã qua)
 560:       - remaining = new_target - sum(actual_enrollments tháng đã qua)
 561:       - Phân bổ remaining theo weights (re-normalize weights cho tháng còn lại)
 562:     Nếu sửa weights hoặc guardrails:
 563:       - Regenerate derived KPIs cho tháng future (skip overridden_fields)
 564:     """
 565: 
 566: async def override_month_kpi(db, plan_month_id, overrides: dict, reason, user_id):
 567:     """
 568:     Admin override 1+ KPI cho tháng cụ thể.
 569:     overrides = {"consultations_daily": 16, "win_rate": 40.0}
 570:     Merge vào overridden_fields, lưu reason + who + when.
 571:     """
 572: 
 573: async def reset_month_override(db, plan_month_id, fields: list[str] | None, user_id):
 574:     """
 575:     Reset override.
 576:     fields = None → reset tất cả → clear overridden_fields → recalculate toàn bộ.
 577:     fields = ["consultations_daily"] → chỉ xóa field đó, giữ các override khác.
 578:     """
 579: 
 580: async def sync_plan_to_kpi_config(db, plan_id, month):
 581:     """

 583:     Upsert vào KpiConfig records (xem section 8.3 mapping chi tiết).
 584:     Ghi effective_month/year + source_plan_id vào KpiConfig.
 585:     Skip upsert khi derived KPI = NULL (WD_t=0, M_t=0, etc.)
 586:     Dashboard đọc từ KpiConfig như bình thường.
 587:     """
 588: 
 589: async def deactivate_plan(db, plan_id, user_id):
 590:     """
 591:     Soft delete: set is_active = FALSE.
 592:     Cleanup: xóa KpiConfig records được tạo bởi plan này cho tháng future.
 593:     Tháng đã qua giữ nguyên (data lịch sử).
 594:     """
 595: 
 596: async def fill_month_actuals(db, plan_id, month):
 597:     """

 857: ### 8.4 Historical target resolution
 858: 
 859: > **Vấn đề**: `get_kpi_target()` không có `effective_date`. Khi dashboard xem kỳ quá khứ
 860: > (VD: xem performance tháng 3), nó lấy target tháng hiện tại (tháng 6) — sai.
 861: 
 862: **Giải pháp**: Thêm `effective_month` vào KpiConfig + resolver.
 863: 
 864: ```sql
 865: -- ⚠️ Tất cả nằm trong CÙNG 1 migration A0 (trước khi tạo bảng kpi_plan ở A1).
 866: -- source_plan_id FK → kpi_plan sẽ thêm SAU ở A1 migration (ALTER TABLE ADD CONSTRAINT).
 867: -- Hoặc tạo column nullable không có FK ở A0, thêm FK ở A1.
 868: 
 869: -- Bước 1: Thêm columns
 870: ALTER TABLE kpi_config ADD COLUMN effective_month INTEGER;  -- NULL = evergreen (legacy)
 871: ALTER TABLE kpi_config ADD COLUMN effective_year INTEGER;   -- NULL = evergreen (legacy)
 872: ALTER TABLE kpi_config ADD COLUMN source_plan_id INTEGER;   -- FK thêm ở A1 sau khi tạo bảng kpi_plan
 873: 
 874: -- ⚠️ UNIQUE CONSTRAINT: Index cũ `uq_kpi_config_scope` trên
 875: -- (unit_id, officer_id, kpi_code, period_type) KHÔNG cho phép nhiều record
 876: -- cùng kpi_code cho các tháng khác nhau. PHẢI thay thế:
 877: 
 878: DROP INDEX IF EXISTS uq_kpi_config_scope;
 879: DROP INDEX IF EXISTS ix_kpi_config_unique_combo;  -- từ perf migration, cũng chặn multi-month
 880: 
 881: -- Unique mới: cho phép 1 record per kpi_code per scope PER THÁNG
 882: -- Evergreen (legacy, effective_month=NULL): tách index riêng
 883: CREATE UNIQUE INDEX uq_kpi_config_scope_evergreen
 884: ON kpi_config (unit_id, officer_id, kpi_code, period_type)
 885: WHERE is_active = TRUE AND effective_month IS NULL;
 886: 
 887: -- Monthly (from planning sync): 1 record per month
 888: CREATE UNIQUE INDEX uq_kpi_config_scope_monthly
 889: ON kpi_config (unit_id, officer_id, kpi_code, period_type, effective_year, effective_month)
 890: WHERE is_active = TRUE AND effective_month IS NOT NULL;
 891: 
 892: -- ⚠️ PERFORMANCE: KpiConfig sẽ phình to khi lưu per-month thay vì evergreen.
 893: -- Mỗi plan sync tạo ~7 records/tháng/officer. 50 officers × 12 tháng = 4200 records/năm.
 894: -- Composite index bắt buộc để get_kpi_target() không full-scan:
 895: CREATE INDEX idx_kpi_config_effective_lookup
 896: ON kpi_config (kpi_code, unit_id, officer_id, effective_year, effective_month)
 897: WHERE is_active = TRUE;
 898: 
 899: -- Sync job ghi: effective_month=3, effective_year=2026, source_plan_id=42
 900: -- Legacy records (admin tạo thủ công): effective_month=NULL → evergreen
 901: 
 902: -- get_kpi_target() resolution order:
 903: -- 1. Monthly record (effective_month/year match) → ưu tiên cao nhất
 904: -- 2. Evergreen record (effective_month IS NULL) → fallback
 905: -- 3. DEFAULT_KPIS → hardcoded
 906: ```
 907: 
 908: ```python
 909: async def get_kpi_target(
 910:     db: AsyncSession,
 911:     kpi_code: str,
 912:     officer_id: Optional[int] = None,
 913:     unit_id: Optional[int] = None,
 914:     period_type: str = "daily",
 915:     effective_date: Optional[date] = None,  # NEW: default=today
 916: ) -> float:
 917:     """
 918:     Inheritance + temporal resolution:
 919:     1. Tìm record có effective_month/year match → dùng target tháng đó
 920:     2. Nếu không có → tìm evergreen record (effective_month=NULL)
 921:     3. Nếu không có → fallback DEFAULT_KPIS
 922: 
 923:     Khi effective_date=None (mặc định): dùng tháng hiện tại.
 924:     Khi xem dashboard kỳ quá khứ: truyền effective_date=date(2026, 3, 15).
 925:     """
 926: ```
 927: 
 928: > **Backward compatible**: Gọi `get_kpi_target()` không truyền `effective_date` → hoạt động
 929: > như cũ (dùng tháng hiện tại). Code hiện tại không cần sửa ngay.

 932: 
 933: > **Vấn đề**: `recommendation_engine.py` hardcode `THRESHOLDS` dict (line 52).

 941:     "consultations_gap_critical": 0.5,   # < 50% of target
 942:     "conversion_rate_low": 10,           # < 10%
 943:     ...
 944: }

 946: # SAU (config-driven, Phase P3):
 947: async def get_recommendation_thresholds(

 966: ### 8.6 Type safety: int → float migration
 967: 
 968: > **Rủi ro**: `KpiConfig.target_value` chuyển từ `INTEGER` → `NUMERIC(12,2)`.
 969: > Backend Python tự xử lý (Decimal/float tương thích), nhưng Frontend TypeScript
 970: > có thể bị ảnh hưởng nếu code cũ dùng integer arithmetic (VD: `Math.floor`, `%`).
 971: 
 972: **Checklist Phase A0 — kiểm tra trước khi deploy migration:**
 973: 
 974: ```typescript
 975: // Frontend: tìm tất cả code dùng target_value hoặc consultations_target
 976: // grep -r "target_value\|consultations_target\|kpi.*target" src/
 977: 
 978: // TRƯỚC (có thể expect int):
 979: const progress = (actual / target) * 100;  // OK — float chia float vẫn đúng
 980: 
 981: // CẦN KIỂM TRA (nếu có):
 982: if (target % 10 === 0) { ... }  // ❌ Modulo trên float có thể sai
 983: const remaining = target - actual;  // OK — float trừ vẫn đúng
 984: 
 985: // Pydantic serialization: NUMERIC(12,2) → Python Decimal → JSON float
 986: // Response: {"target_value": 16.7} thay vì {"target_value": 16}
 987: // TypeScript: number type xử lý cả int lẫn float → an toàn
 988: ```
 989: 
 990: > **Kết luận**: Rủi ro thấp vì TypeScript `number` = float64. Chỉ cần audit
 991: > code frontend tìm integer-specific operations (`%`, `parseInt`, bitwise).
 992: > Backend `KPIStats` schema giữ `float` type → không ảnh hưởng.

1056: ## 10. Edge Cases & Business Rules
1057: 
1058: ### 10.1 Sửa annual_target giữa năm
1059: 
1060: ```
1061: Ví dụ: T6, admin đổi target 300 → 350
1062: 
1063: Tháng 1-5: đã có actuals, KHÔNG đổi enrollment_target
1064:   actual_sum = sum(actual_enrollments cho T1-T5) = 84
1065: 
1066: remaining = 350 - 84 = 266
1067: 
1068: Phân bổ remaining cho T6-T12:
1069:   sub_weights = normalize(weights[6:12])  # Re-normalize cho 7 tháng còn lại
1070:   M_t = round(266 × sub_weight_t) + reconciliation
1071: 
1072: Derived KPIs cho T6-T12 recalculate theo M_t mới.
1073: ```
1074: 
1075: ### 10.2 Soft-delete plan giữa năm
1076: 
1077: ```
1078: 1. Set kpi_plan.is_active = FALSE
1079: 2. Cleanup KpiConfig: soft-delete records cho tháng current + future
1080:    (WHERE source_plan_id = plan_id
1081:       AND effective_year = fiscal_year
1082:       AND effective_month >= current_month)
1083:    → SET is_active = FALSE
1084: 3. Tháng đã qua (effective_month < current_month): giữ nguyên (data lịch sử)
1085: 4. Officer dashboard: fallback về evergreen KpiConfig hoặc DEFAULT_KPIS
1086: ```
1087: 
1088: ### 10.3 Nhiều officer plans trong cùng unit — phân bổ linh hoạt
1089: 
1090: #### Mô hình: Unit plan = baseline, Officer plan = override cá nhân
1091: 
1092: ```
1093: Unit plan: annual_target = 1200 → baseline cho officers chưa có plan riêng
1094: Officer A plan: annual_target = 300 → override cá nhân
1095: Officer B plan: annual_target = 300 → override cá nhân
1096: Officer C: không có plan riêng → dùng unit plan (baseline = 1200)
1097: Officer D: không có plan riêng → dùng unit plan (baseline = 1200)
1098: ```
1099: 
1100: #### Quy tắc phân bổ
1101: 
1102: > **Thiết kế chốt**: Unit plan target KHÔNG tự động chia đều cho officers.
1103: > Unit plan là **target chung** (baseline) — mỗi officer không có plan riêng sẽ dùng
1104: > nguyên target unit plan. Officer plan là **target cá nhân** hoàn toàn độc lập.
1105: 
1106: | Scenario | Hành vi |
1107: |----------|---------|
1108: | Officer có plan riêng | Dùng officer plan, bỏ qua unit plan hoàn toàn |
1109: | Officer KHÔNG có plan riêng | Dùng unit plan target nguyên (không chia) |
1110: | Tổng officer plans > unit plan | **Cho phép** — admin chịu trách nhiệm. Không validate |
1111: | Tổng officer plans < unit plan | **Cho phép** — phần còn lại chưa giao cho ai cụ thể |
1112: 
1113: #### Tại sao không auto-distribute?
1114: 
1115: 1. **Complexity**: Chia 1200 cho 5 officers cần biết capacity/seniority mỗi người → quá phức tạp cho MVP
1116: 2. **Flexibility**: Admin muốn giao khác nhau (senior 300, junior 100)
1117: 3. **Hiện thực**: Các trường thường giao KPI cá nhân qua Excel, không chia đều
1118: 
1119: #### Validation/Warning (UI, không block)
1120: 
1121: ```python
1122: # Admin Planning UI hiện warning (không block save):
1123: total_officer_targets = sum(officer_plan.annual_enrollment_target for active officer plans)
1124: if total_officer_targets > unit_plan.annual_enrollment_target:
1125:     warning = f"Tổng chỉ tiêu officer ({total_officer_targets}) vượt chỉ tiêu unit ({unit_plan.annual_enrollment_target})"
1126: if total_officer_targets < unit_plan.annual_enrollment_target:
1127:     remaining = unit_plan.annual_enrollment_target - total_officer_targets
1128:     info = f"Còn {remaining} chỉ tiêu chưa giao cho officer cụ thể"
1129: ```

1132: 
1133: ```
1134: Sync job xử lý từng officer active trong unit:
1135:   1. Tìm officer plan (WHERE officer_id = X AND is_active = TRUE)
1136:   2. Nếu có → dùng officer plan targets
1137:   3. Nếu không → dùng unit plan targets (nguyên, không chia)
